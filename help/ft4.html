OscarWatch includes an in-app OscarWatch FT4 window for duplex satellite work: decode, transmit, PTT, auto-sequence, echo uplink calibration, and logbook save. Open it from Tools → OscarWatch FT4.

Opening OscarWatch FT4

Go to Tools → OscarWatch FT4. Only one FT4 window is open at a time; choosing the menu again brings the existing window to the front. Focus a satellite on the main map so uplink and downlink Doppler readouts stay useful during a pass. Set your callsign and Maidenhead grid under Settings → Station before enabling transmit.

OscarWatch FT4 is for linear/USB-style modes only. The Tools menu item is disabled, and transmit is blocked, when the focused mode is FM, when FO-29 is focused (its licence does not allow this digital mode), or when AO-7 is focused (AMSAT has asked that FT4 not be used there).

On ICOM radios that report RF power over CI-V (for example the IC-9700), and on Yaesu FT-991 / FT-991A (CAT PC;), OscarWatch reads the set power before transmit. If it is more than 30 W, transmit is blocked until you turn the RF power control down. Radios that cannot report power are not blocked by this check.

What you will see

  • Waterfall: scrolling spectrogram of the USB audio passband (about 200–3000 Hz). Click the waterfall to set RX, and TX as well unless Hold Tx Freq is on. Green brackets mark the FT4 filter around RX (±45 Hz), with a horizontal bar joining the two legs at the top. While you are in a QSO they stay on that station. Red brackets always mark TX and stay inside the waterfall. Decodes appear in the list with their audio frequency so you can match RX and TX.
  • Slot clock: UTC FT4 slot timing (7.5 s), including even/odd slot.
  • Doppler: uplink and downlink radio frequencies from OscarWatch tracking for the focused satellite.
  • Decodes: messages decoded in the current session, including DT (time offset). TX is the message OscarWatch sent (no SNR, a dash in the DT column). Echo is that transmission decoded from the receiver, with the SNR and audio frequency that came back. A trace on the waterfall is not an Echo until the decoder copies it. Full-duplex copies often start late in the slot; OscarWatch searches that later audio on your TX slots.
  • TX message: text you will transmit; use CQ to build a standard call from your station callsign and grid.

Transmit and auto-sequence

  • Enable Tx: arms transmit for the current message on the next matching slot.
  • Halt Tx: stops further transmits immediately.
  • CQ: starts a CQ using your callsign and grid, then auto-sequences replies (report, RRR or skip to 73).
  • Report and 73: send that message again to the station in the current QSO. Report reuses the signal report already sent. Both need a QSO in progress.
  • Skip RRR: when checked (default), finished QSOs go straight to 73.
  • Even TX slots: prefer even FT4 slots for your transmit side.
  • Clear / Save activity: clear the decode list, or save band activity to a text file.
  • Log QSO: manually save the current contact to the OscarWatch Logbook (needs their callsign from an answered decode or CQ reply). Auto-log still runs when a QSO finishes with both reports. An open Logbook window adds the contact straight away. If that logbook has Cloudlog auto-upload on, the contact is uploaded as well.
  • Hold Tx Freq: keep your TX audio Hz when answering (default); clear it to jump to the decode frequency.
  • TX audio (Hz): audio tone within the USB passband (default 1500 Hz).
  • Settings: soundcards, TX level, PTT method, PTT lead/tail, audio-domain Doppler on/off, decode text size, and echo uplink trim.

Click a decode addressed to you to answer and join the QSO. The sequencer drives the next messages until the contact completes.

PTT methods

Choose how OscarWatch keys the uplink (in FT4 Settings):

  • VOX / audio: play TX audio only; your radio or interface keys from audio.
  • CAT: key via the connected radio’s transmit command.
  • CAT port RTS/DTR: assert RTS or DTR on the open CAT serial port.
  • Separate COM port: dedicated handshake port for PTT (must not be the same COM port as the radio, rotator, or GPS).
  • Manual (prompt): OscarWatch asks you to key and unkey for each slot.

Echo uplink calibration

When you decode your own uplink echo, OscarWatch stores a per-satellite uplink offset and applies it to Doppler CAT for FT4 so your signal sits where you hear it. Open FT4 Settings to view, edit, or clear the uplink trim (Hz) for the focused satellite, or clear all stored calibrations.

Slot-gated Doppler (OrbitDeck-compatible)

While the FT4 modem is running, CAT Doppler is held for each 7.5 s slot and only stepped at the slot boundary. Within the slot, OscarWatch cancels residual drift in the audio domain: TX pre-compensation (with LSB sign flip on inverting birds) and RX Hilbert de-Doppler before decode. That matches OrbitDeck for iOS FT4 so your burst stays sharp in the passband.

Audio and PTT

Open Settings in the FT4 window to choose the input and output soundcards (separate from pass-recording devices in the main Settings), PTT method, lead/tail timing, whether audio-domain Doppler correction runs on TX and RX, the decode text size, and echo calibration uplink trim. For RTS/DTR methods, choose the handshake line (and COM port when using a separate PTT port). TX level is also set there.

With a Virtual Audio Cable (or similar), play FT4 TX into CABLE Input and set WSJT-X (or the radio) to listen on CABLE Output. FT4 opens the low-latency shared Windows audio path for that device, so the cable can still be shared, and keeps the output open while the modem is running. The burst is built before the slot. The tone itself follows a half-second lead-in, which is part of FT4 timing. After changing soundcard settings, use Refresh and re-select the cable if another app suddenly loses audio.

Logging

Completed FT4 contacts are saved to the built-in OscarWatch Logbook when the QSO finishes (73 / RR73), or sooner via Log QSO if you want to record a partial contact. You can still log manually from Tools → OscarWatch Logbook.

Native library

Encode and decode use a bundled native library (oscarwatch_ft8) based on ft8_lib (MIT). Release packages ship the matching binary for each platform:

  • Windows: oscarwatch_ft8.dll
  • macOS: oscarwatch_ft8.dylib (Apple Silicon osx-arm64 and Intel osx-x64)
  • Linux: oscarwatch_ft8.so

If the status line reports that the native library is missing, rebuild or reinstall so the file sits next to the application or under runtimes/<rid>/native/. See native/oscarwatch_ft8/README.md for a local CMake build.
